# Z002 楼层范围补图

## 交付

版本为 `0.8.54-native.2`，开发分支为 `task/Z002-backfill-images`。
安装地址为 `https://github.com/ambroselbt28-gif/zhiku-native-comic`，更新现有扩展即可。

「漫画」页与「设置」的正文插图提示词区域增加「补未生图楼层」。可选择普通插图或漫画，填写包含两端的楼层编号范围。

普通插图复用 `illustrationPlanner` 的正文转方案、副 API 请求、方案验证、锚点插入与保存，再由标记控制器生成图片。漫画复用既有 `adapt` 与整页生图流程。副 API 分别读取功能配置 `ill` 与 `comic`，窗口展示文字 API 来源。

当前候选已有智库图片或正文 HTML / Markdown 图片时跳过，状态栏图片按正文边界剔除。没有图片但已有标记或分镜时直接出图。用户消息、真实系统消息与工具消息按角色回复检查过滤，人工隐藏的角色回复可以手动补。

逐楼串行处理，已有任务跳过。失败楼层列出错误，后续楼层继续。再次运行相同范围会补剩余无图楼层。停止后等待当前楼层收尾，切换聊天后停止继续调度。消息对象、正文或候选回复变化时，排队楼层会跳过，在途结果继续走原有快照校验。

## 源文件与接口

- `src/image-backfill.js` 实现范围扫描、调度、进度与弹窗。
- `tools/image-backfill.mjs` 接入实际页面按钮、插件初始化与停用、聊天切换清理。
- `src/illustration-runtime.js` 新增 `backfill(id)` 与 `status(id)`，沿用原有 `after` 和 `selected` 行为，并共享楼层忙碌保护。
- `src/marker-generation.js` 新增 `status(id)`，返回当前候选的图片、缺图标记、忙碌与错误。手动标记生成兼容隐藏的角色回复。
- `src/comic.js` 新增 `status(id)`。空地址的旧版本记录可再次补图。
- `runtime.js`、`manifest.json`、`package.json` 已重建并随提交发布。

## 人类验收步骤

1. 打开手机 TT 的扩展管理，在「智库 · NAI5 原生漫画二改」点击更新，完全退出后重开 TT。
2. 打开智库「设置 → 关于」，确认版本为 `0.8.54-native.2`。
3. 到「AI 预设 → 各个功能」，将「正文插图」或「漫画改编」设置为想使用的副 API，生图接口沿用自己的配置。
4. 打开要补图的聊天，在智库「漫画」页点击「补未生图楼层」。也可从「设置」的正文插图提示词区域进入。
5. 选择「普通插图」或「漫画」，填写聊天中显示的 # 楼层编号，例如起始 `79`、结束 `83`。若只补第 79 楼，两格都填 `79`。
6. 点击「开始补图」。应看到逐楼进度，已有图楼层显示跳过，成功图片回到原楼层。
7. 中途点击「停止补图」，应显示等待当前楼层收尾，后续楼层显示尚未执行。
8. 有失败楼层时，修正对应接口或模型错误，再对同一范围点击「开始补图」，检查已有图片楼层跳过，剩余楼层补图。

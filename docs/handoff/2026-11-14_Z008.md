# Z008 官方连接测试与网络提示

## 交付

版本为 `0.8.54-native.8`，分支为 `task/Z008-nai-connection`。
安装仓库为 `https://github.com/ambroselbt28-gif/zhiku-native-comic`。

用户反馈手机 NAI 官网可用，随后确认使用官方 Key，实际标记出图报 `Failed to fetch`。这条错误说明前端未获得可读取的 HTTP 响应，当前还需要手机联网和代理配置证据。

检查时发现连接测试仍查旧的 `https://api.novelai.net/user/subscription`。SillyTavern release 的 NovelAI status 已使用 `https://image.novelai.net/user/subscription`，本次同步迁移。此修复针对连接测试，用户的实际生图失败仍待手机验证。

连接测试网络异常现在返回 `ok: false`，显示 Key 与生图状态尚待验证。实际出图的网络提示改为「未收到可读取的响应」，并提示检查 TT 是否纳入手机分应用代理。浏览器 fetch 异常无法证明服务端是否收到请求。

## 验证

- `node tools/build-extension.mjs` 成功。
- `node tests/nai-connection.mjs` 执行正式 NAI 模块，验证新域名、鉴权头、余额、401/403/429/500、网络异常和第三方通道兼容。全部使用模拟接口。
- `node dev/selftest.mjs` 共 51 个测试文件通过。调整网络提示后再跑 `nai-connection`、`nai-request-compat` 和 `tauri-fetch` 均通过。
- 三档浏览器正式入口检查各 44 项，共 132 项通过。
- `git diff --check` 通过。新增业务构建行 grep 检索聊天写接口、`saveChat`、删除和元数据保存函数及 `swipe_id` 赋值，命中 0。
- 对官方出图端点仅发送无 Key 的 OPTIONS 探测，当前开发机对 `https://novelai.net` 与 `http://tauri.localhost` 均返回允许来源 `*` 且允许 Authorization、Content-Type。此结果限于开发机，手机实际网络仍待确认。
- 未调用真实付费出图，未读取宿主聊天数据，未改动 ST Reader 工程。临时测试目录继续使用已忽略的本仓库 `.tmp/`，沿用之前自动审批拒绝递归清理后的目录。

## 人类验收步骤

1. 更新智库并退出重开 TT，关于页确认 `0.8.54-native.8`。
2. 如果手机代理启用了分应用设置，确认 TauriTavern 已在代理名单。
3. 打开「智库 → 设置 → NovelAI → 测试」，查看官方 Key 的订阅查询结果。
4. 再对此前失败的楼层点击生成。仍失败时保留问题记录里的错误、时间及 TT 前端日志，遮住 Key。

## 给下一个人的话

需要区分连接测试失败和实际生成失败。当前生图本来已使用 image 域名，修正订阅接口不能证明手机实际出图恢复。继续根据代理应用名单和手机日志诊断，避免把通用 fetch 异常直接定性为 Key 无效或服务端未收到请求。

# Z009 官方联网稳定性

## 交付

版本为 `0.8.54-native.9`，分支为 `task/Z009-nai-network`。
安装仓库为 `https://github.com/ambroselbt28-gif/zhiku-native-comic`。

用户确认同一部手机、同一个官方 Key 和官方图像地址，柏宝绘能够实际出图，智库间歇出现长时间等待后的 `Failed to fetch`，切到手机流量仍失败。

核对柏宝绘源码提交 `1f5b9f6d443281b088e3910ea578d4088260d324` 的 `src/backends/nai.ts`、`naiRateLimit.ts` 与 `naiAccount.ts`。两者都直接访问官方图像服务。柏宝绘有 240 秒出图超时和网络错误重试，智库原先只重试部分 HTTP 错误。这些差异可以解释失败处理能力不同，实际手机根因仍需新版本日志验证。

## 行为

官方请求通过独立同源空白 iframe 的浏览器 fetch 发送，减少页面包装器干扰。通道创建失败时沿用原页面 fetch。实际请求失败后由有界队列处理，同源宿主和第三方地址继续使用原来的页面联网路径。

官方生图每次最多等待 240 秒，计时覆盖收到响应头后的图片数据读取与解析。超时会取消请求，停用扩展也取消当前官方请求并移除独立通道。用户取消和停用以 AbortError 结束。

官方网络错误与超时最多重试两次，分别等待至少 5 秒和 10 秒，界面显示次数。首发前固定种子，随机种子输入也在重试间沿用。既有 HTTP 限流和服务端退避继续使用原有队列。

网络中断无法确定服务端是否已经接收原请求，自动重试可能发生重复扣点。本次选择默认最多两次网络重试，已在 README 和用户交付中说明。

连接测试只读官方订阅，最多等 15 秒。失败记录增加每次尝试耗时、目标地址、等待响应/读取数据/解析图片阶段和实际 fetch 通道。当前日志继续按原有字段省略图片及 Key。

## 文件与接口

- `src/nai-network.js` 提供 `createNaiNetwork`，包含 fetch、run、kind 与 stop。
- `tools/nai-network.mjs` 接入正式 NAI 模块、出图、订阅查询和关闭清理。
- `src/nai-gate.js` 的 run 新增默认关闭的 `retryNetwork` 选项，官方出图显式开启。
- `src/nai-request-compat.js` 固定同一张图的重试种子。
- `src/site-post.js` 增加失败阶段，沿用原有返回描述的字段顺序。
- `tests/nai-network.mjs` 检查源码与发布代码的隔离联网、域名边界、超时、取消、停用及重试次数。
- 既有问题记录和正式请求测试接入网络控制器，检查返回值、原始错误和来源仍可保留。

## 人类验收步骤

1. 手机 TT 扩展管理更新智库二改，退出重开 TT，关于页确认 `0.8.54-native.9`。
2. 使用原来的官方 Key，在智库设置点 NovelAI 测试，最长等待 15 秒。
3. 在此前失败的正文楼层生成一张。网络错误时应看到等待和重试次数，成功图正常插入原楼层。
4. 如果最终仍失败，打开「设置 → 问题记录」，复制最新生图失败条目的耗时和返回信息。返回信息应含目标地址、阶段和独立浏览器 fetch。
5. 如需中止整个扩展，在扩展管理中停用智库，当前请求及排队重试应结束。

## 给下一个人的话

同机柏宝绘可以实际出图是继续诊断的重要对照。仍需核对手机实际失败阶段，不能仅凭增加重试宣称根因已经定位。官方请求默认独立联网是本次兼容选择，后续保持宿主只读接口路由和其他第三方联网行为。

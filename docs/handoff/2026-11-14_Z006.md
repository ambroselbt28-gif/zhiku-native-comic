# Z006 人物自动建档与外貌方案

## 交付

版本为 `0.8.54-native.6`，分支为 `task/Z006-auto-character-profiles`。
安装地址为 `https://github.com/ambroselbt28-gif/zhiku-native-comic`。

用户确认重roll指人物外貌方案。角色页新增默认开启的首次出场自动建档开关，新正文用 `look` 功能的副 API 识别实际出场人物，已有外貌和同人身份继续沿用。新人物进入智库原有角色库与当前聊天候选名单，后续配图调用已存外貌。

正文未交代的外貌可由 AI 设计，档案标注含 AI 补全。服装单独存为初见服装，固定外貌过滤常见临时视线、动作与表情。候选资料可提供角色设定，识别结果需要有当前正文中的出场原句及实际出现的名字或别名。

人物页的「外貌方案 · AI修改」提供重roll外貌、自然语言修改、方案前后切换和试画当前方案。新的外貌立即保存到角色库，最近 10 次生成保留为历史方案，手动编辑过的当前标签也会在切换前保存。相同英文标签的排列或中文释义变化会提示仍为同一方案。

同人角色的显式外貌修改保留角色标识并启用 `canonKeepLook`，使新外貌进入实际请求。已有角色的手工编辑入口继续可用。

## 请求与一致性

新正文会多一次「读角色外貌」文字请求。相同消息并发识别共享任务，扫描签名剔除图片标记并归一空白，以 64 位签名保存在插件选项中，重载与插图后复用。显式扫描按钮可强制重试。

自动插图、标记出图、漫画改编都在使用人物标签前等待建档准备，正文事件入口先完成识别再继续原有配图。自动扫描只处理当前新角色回复，手动出图可以处理隐藏的角色回复。

聊天、候选回复、正文或数据对象变化时丢弃在途识别。自然语言和重roll还检查当前档案指纹，避免覆盖用户后来修改。插件停用或切聊天增加代次，旧结果失效。存档失败回滚本次人物、聊天候选与扫描记录，并保留并发手工修改。

本次只持久化智库 `characters`、`chatCast` 与 `options`，通过现有插件存档入口写入。角色历史保存在 `autoProfile` 元数据中，实际聊天正文与聊天候选回复由宿主管理。

## 人类验收步骤

1. 在手机 TT 扩展管理中更新智库二改，退出并重开 TT，确认关于页版本为 `0.8.54-native.6`。
2. 打开智库「角色」，确认「首次出场自动建档」开启。在「AI 预设 → 各个功能 → 读角色外貌」选好副 API。
3. 让新正文出现一个新的有名人物，等待建档通知。打开「角色」的当前聊天名单或「存下的」列表，应能找到新人。
4. 点进人物，在「固定外貌」旁点击「外貌方案 · AI修改」，检查首次标签与 AI 补全标记。
5. 点击「重roll外貌」，等待新英文标签保存，再点「试画当前方案」，检查角色预览使用新标签。
6. 再打开方案窗口，输入「改成银色短发，保留蓝色眼睛」，点击「按意见修改」。修改完成后，标签应随意见变化。
7. 点「上一方案」与「下一方案」，检查历史标签可切换。后续正文配图应使用当前选定的角色外貌。
8. 若接口失败，可先修正配置，再在角色页点「扫描当前回复的人物」。需要停用自动调用时关闭首次建档开关。

# Z020 多套固定外貌

## 交付

版本 `0.8.60-native.19`，分支 `task/Z020-saved-appearance-presets`。用户要求保存多套固定外貌，避免每次逐个删除标签。发布沿用 https://github.com/ambroselbt28-gif/zhiku-native-comic 。

## 行为与数据

- 固定外貌按钮改为「外貌方案 · 存取 / AI」，弹窗增加方案命名保存、方案选择及使用、整套粘贴替换、一键清空。
- 每个人物的 `appearancePresets` 保存 `{id,name,at,appearance}` 数组。命名方案与 `autoProfile.versions` 最近历史分开，不随历史最多 10 条的裁剪删除。同名拒绝，不静默覆盖。英文及中文标签深拷贝，应用时替换整个数组。
- 控制器新增 `savePreset`、`applyPreset`、`replaceAppearance`、`clearAppearance`；沿用持久化、并发锁、回滚与刷新，不写宿主聊天。新增数据参与指纹，避免在途 AI 结果覆盖新方案。
- 应用/替换/清空前当前手动标签进入最近历史；清空也保存空状态作为新历史，上一方案可恢复原标签。长期需要的版本应命名保存。
- 手动粘贴允许逗号/换行，双冒号权重内部逗号保持一项，权重不成对或中文/协议混入时报错。手动标签不经过 AI 外貌过滤；相同英文标签保留已有中文释义，不调用翻译。
- 衣服、负面、参考图与同一人物其他字段保持原值，命名方案只管理固定外貌。人物切换沿用角色 key，跨人物不共享方案。
- 无删除方案功能，本任务不自动删除旧标签快照或清理历史以外的用户方案。

## 验证

- 正式构建成功，`node dev/selftest.mjs` 62/62 个测试文件通过。Node 源码/发布代码覆盖多套保存、重载、整套替换、权重、AI 历史淘汰不影响保存方案、当前标签与快照隔离、清空恢复、四种操作持久化失败回滚、AI 在途锁与 AI 修改保留保存方案。
- 浏览器在 390、768、1366 三档各 111 项通过，共 333 项。正式人物按钮和弹窗完成保存两套、批量替换、清空/上一方案恢复、应用旧方案以及试画使用选定标签。
- 使用合成档案与请求，无付费调用、真实宿主数据读取、依赖安装或 C/F 写入。沿用 `.tmp` 测试缓存。

## 人类验收步骤

1. TT 扩展管理更新智库，关闭面板等待空闲重载，确认版本 `0.8.60-native.19`。
2. 打开「智库 → 角色 → 人物详情 → 固定外貌 → 外貌方案 · 存取 / AI」。填「黑发原版」，点「保存当前外貌为新方案」。
3. 展开「粘贴整套标签 / 一键清空」，粘贴另一整套英文标签，点「整套替换当前外貌」，再命名保存为第二套。
4. 从列表选择第一套，点「使用选中方案」，应完整恢复第一套而没有第二套残留标签。重开智库仍可选择这两套。
5. 点「一键清空当前外貌」应清空当前标签，已存方案仍在；点「上一方案」恢复清空前的标签。
6. 后续正文图或「试画当前方案」使用当前外貌。试画会调用生图接口并正常消耗额度；仅存取/切换不消耗。

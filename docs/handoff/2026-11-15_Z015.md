# Z015 漫画人物归属与分镜校对

## 交付

版本 `0.8.60-native.15`，分支 `task/Z015-comic-scene-grounding`，安装地址沿用 https://github.com/ambroselbt28-gif/zhiku-native-comic 。

用户把 CFG 调到 5 后仍反馈画面异常。本任务针对已经从最新日志与代码确认的分镜组织问题改进提示词，不再把 CFG 或联网当作画质问题的确定原因。

## 证据与边界

- 用户所提供日志最新四次成功请求使用 NAI 5 Full。分镜中有手机屏幕特写同时放入完整双人、近景要求踢行李箱、同格描述先后动作，以及发送文本里的 C1 指代缺少身份声明。
- 原请求虽然有每格人物条目，所属画格说明却位于长外貌描述之后；普通规则四格也没有人物坐标，截图中多格构图近似。不能仅凭这些证据证明某一项就是画风异常的唯一原因。
- 仅分析用户指定日志与截图；仓库测试全部使用合成剧情，不复制其人物资料或日志到公开仓库。
- 参考本次阅读的 NAI5 漫画技能与官方多人物文档，见 `docs/NAI5_PROMPT_REFERENCES.md`。未发布技能参考里的私人社区原图、完整提示词或源码包。

## 变更

1. `parseComicPage` 的 native 请求描述声明人物身份与出场画格；每格列出主角编号。旧协议、哈希、保存的原始分镜、对白与历史图片保持原有存储方式。
2. `comicRequest` 把画格范围和身份放到人物描述开头，保留 Text 在最后。规则上下分格、规则网格和明确四等分条漫推导人物位置，同格多人横向分开，并使自动定位人物栏按空间顺序排列。日式阅读顺序保留在画格编号里。
3. 位置不明确、重复、斜格、嵌套、不规则或跨页不推导坐标；用户已有手写坐标优先。漫画设置新增默认开启的「按画格定位人物」，关闭可恢复自动安排。这个选项只影响推导坐标。
4. AI 改编/单页重写新增逐格校对：一个瞬间、镜头范围、谁看谁、持物与接触归属、人物身份、构图差异。保留用户的画师和采样参数；不自动补写实、3D 或高权重质量词。
5. 编辑器实时提示物件特写与多人物、近景腿脚、先后动作、未定义人物等潜在冲突。只提示，不自动删除人物或改剧情。AI 重写拿到当前编辑草稿和原楼正文，默认修镜头动作，仍使用已有副 API 与生图流程。
6. 已有图需用户触发重画。保留分镜重画会用新编译，但语义冲突要通过「让 AI 重写本页」或重新改编才能改变。

## 人类验收步骤

1. 手机 TT 更新二改智库至 `0.8.60-native.15`。已启用 native.14 自动重载的等成功提示；还运行 native.12/13 的需首次退出重进一次。
2. 在「漫画」设置确认「按画格定位人物」开启，保持当前画师和 CFG 5，方便对照。
3. 在聊天楼层点出问题的漫画图片，点「编辑本页」。如果当前分镜有镜头/动作冲突，会在编辑区下方提示。
4. 点「让 AI 重写本页」。此操作调用漫画副 API 并生成新图，默认要求已包含镜头、动作、人物关系修正；旧图片可切回。
5. 若只想对照定位变化，使用「重画这一页」，它保留旧分镜；不要把这个入口当作语义重写。
6. 查看新图的角色归属、相邻格动作与镜头差异；若仍不满意，提供新图及该页「实际发送」继续对照。真实审美效果待用户验收。

## 给下一个人的话

坐标由明确的规则布局推导，并非视觉识别出的真实画格边界，模型也不保证严格服从；不要对不规则页面盲目给相同中心点。当前没有自动从另一个人的外貌生成负面，避免误抑制共享特征。不要添加质量词或更换画师来掩盖尚未验证的画风根因。

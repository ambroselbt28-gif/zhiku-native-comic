# Z029 基于预设1生成古风副本

版本 `0.8.60-native.28`，分支 `task/Z029-ancient-ai-preset`。

用户要求基于自己的预设1加古风主提示词和更完整的思维链。用户已提供日志能确认“流光主指令 + 上下文 + 思考条目”的结构，但日志条目是摘要，不能还原私人预设全文。本次在本机生成副本，完整复制当前选中自定义预设，不拿日志摘要替代原文、不将私人条目提交仓库。

- 纯函数 `createAncientPreset(cfg, uid)` 返回 `{preset,created}`。复制条目，主提示词插在上下文前，独立思维链补充放最后；原有条目、角色、启用状态和先后顺序保留。缺上下文时补齐。名称冲突加序号，同来源重复点击复用已有副本，保留用户修改。
- 面板新增「生成古风副本」，只对自定义预设显示；成功后选择副本并调用原有插件配置提交。原预设不变，功能 API/模型映射不变。不做自动迁移或按角色卡绑定。
- 内容检查时代/身份、衣装发饰、建筑器物、镜头光线、目光/手/衣袖关系、tag 与英文行动句、漫画连续性、协议输出。使用泛古风默认，尊重明确时代与穿越设定，不硬编码具体史实或万能古装词；不覆盖用户画师风格。
- 参考本地「COT条目写作」技能的模块化与具体可判定检查。当前任务是生成绘图协议，最终只输出任务结果，避免显性分析破坏 JSON。用户已明确授权增加这组规划规则，无需额外确认阶段。

验证：`node tools/build-extension.mjs`；`node dev/selftest.mjs` 64 个 Node 文件；`node dev/browser-selftest.mjs` 390/768/1366 三档各 143 项（429 项）。新增回归检查原配置不变、深复制、关闭条目保留、上下文位置、去重/改名/重载、正式消息入参及切回原预设隔离。三档通过正式按钮创建、显示条目、重复点击与切回。未调用付费生图服务，风格改善待用户实际验收。

新增业务行禁写聊天模式 `/api/chats/(save|rename|delete|import|group/save|group/delete|group/import)|saveChat\s*\(|deleteMessage|deleteLastMessage|renameChat|clearChat|addOneMessage|updateChatMetadata|saveMetadata|swipe_id\s*=(?!=)`：0 命中。未读真实聊天库或写 C/F 盘、安装依赖；只读用户明确提供的日志定位原条目结构。

人类验收：更新到 native.28，点「图」→设置→AI 预设→选中「我的预设 1」→「生成古风副本」。应出现并选中「我的预设 1 · 古风」，条目列表新增古风主提示词和思维链补充，原预设还在。重新生成古风剧情的画面方案后查看 tag 与英文句子。换现代卡时切回「我的预设 1」。只重画旧图片会沿用旧方案，不会触发新文字规则。

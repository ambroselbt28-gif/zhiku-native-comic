# Z016 官方联网通道对照与诊断

## 交付

版本 `0.8.60-native.16`，分支 `task/Z016-nai-transport-diagnostics`，沿用 https://github.com/ambroselbt28-gif/zhiku-native-comic 安装仓库。

用户同意在核对 TT 2.4.0 后增加页面/独立 iframe 联网对照、修正错误识别并补日志。未修改 TT 或 ST Reader。

## 依据与边界

- 核对 TT v2.4.0 修复重发构建 `fff9af0333be97697be2313981699ab0ce35c236` 的 `src/tauri/main/bootstrap.js`、`interceptors.js`、路由和 Android WebView 源码；外部 NAI 地址不经过同源 Rust API 分流。
- 智库正文、角色图和漫画共用 NAI 请求路径。隐藏 iframe 也是浏览器 fetch，不能声称它是原生代理或已排除跨域问题。
- 使用 Node 隔离 realm 和实际浏览器 iframe 验证：子窗口 TypeError 不属于父窗口 TypeError，原 instanceof 判断会漏掉网络错误。这是错误提示缺陷，不证明它造成了联网失败。
- 新日志只记录浏览器能够暴露的错误；如果原始信息只有 Failed to fetch，不能推断具体的 CORS/TLS/代理原因。

## 行为与接口

- 设置 `naiNetworkMode` 默认 `isolated`，可切为 `page`，沿用原设置保存机制。下一次请求生效，不改变模型、提示词、种子或 Key。
- `createNaiNetwork` 新增可选 `getMode`；`fetch(input, init, info)` 的第三参数为逐请求诊断对象，旧的二参数调用兼容。`kind` 保留；新增 `errorText` 遮蔽已知 Key、Bearer 与 pst Token。
- 页面模式不创建 iframe；独立模式仅在创建失败时回落页面并明确记录，不在 POST 请求失败后自动跨通道重发。原有同通道最多两次网络重试与 240 秒超时不变。
- `probeNaiNetwork` 串行查询两路 `/user/subscription`，每路最多 15 秒，重复点击复用在途 Promise，不改变配置、不付费生图。当前选择的普通连接测试也记录结果。
- 每次请求独立记录选择/实际通道、页面 origin、可见状态、navigator 在线提示、UA、响应头等待时间、错误名称和信息。读取数据与解析阶段沿用原诊断。设置和错误日志不读取或保存手机系统日志。
- 成功生图记录也显示通道；生成前复制设置摘要，避免同时切换设置让失败日志误报旧请求的 Key 或模式。鉴权头和堆栈不写入日志。
- `netError` 改用跨 realm 可用的错误名称识别；文案不再只指向代理名单。

## 人类验收步骤

1. 手机 TT 扩展管理更新现有二改智库。若智库面板或漫画阅读器还打开，先关闭，等自动重载；关于页确认 `0.8.60-native.16`。
2. 打开智库 → 设置 → NovelAI，选择自己填写官方 Key，找到 Key 下方「官方联网通道」。
3. 点击「对照测试两种通道（不生图）」，最长约 30 秒。应显示页面联网与独立 iframe 联网各自结果；设置 → 问题记录出现两条「NAI 通道测试」。
4. 把「官方联网通道」改成「页面联网（对照用）」，回到此前失败的同一正文图点重新生成。此操作会正常调用付费生图；插件不会自行提交对照生图。
5. 若仍失败，导出问题记录，比较新测试与生图记录中的通道、耗时和阶段。订阅测试成功不能当作生图已恢复。
6. 切回独立 iframe 后再次打开设置，应保留选择。其他第三方站点和宿主接口不改变路径。

## 给下一个人的话

不要把本版描述为已解决网络根因。先拿用户同机、同一时段的通道对照。生图请求无法确认服务端是否已接受时，不要另加隐式跨通道重试，避免增加重复扣费。

# Z014 更新完成后自动重载智库

## 交付

版本 `0.8.60-native.14`，分支 `task/Z014-update-reload`，沿用安装仓库 https://github.com/ambroselbt28-gif/zhiku-native-comic 。

接入宿主 manifest `hooks.update: onUpdate`。更新成功只切换智库 runtime，使用带缓存参数的动态 import，不刷新整个聊天页、不主动安装更新、不包裹宿主 fetch。扩展设置提供「重载智库」重试入口。

## 行为与实现

- `src/update-reload.js` 管理串行启动、更新、停用与删除，重复更新合并；加载新版失败保留旧实例，启动失败清理新版后尝试恢复旧工厂。
- 活动计数跟踪 NAI、引擎、LLM、标记、存储、角色和共享模块，以及建档、正文规划、漫画和补图控制器返回的完整 Promise，覆盖排队、重试、保存及批量操作。同步返回值和 Promise 身份保留。
- 最后操作结束后至少安静 3 秒；智库主面板、编辑弹窗、图片查看器、漫画阅读器仍打开，或宿主正在生成正文、页面在后台时继续等待。导入新模块后再检查一次，避免下载期间新任务被打断。
- 停止旧实例先停计时器、拆入口并清理监听，再等待旧存储 flush；沿用现有存储接口。新实例启动后报告实际 runtime 版本。
- 引导代码保持稳定，运行时更新无需重新执行 index。今后修改引导协议或 manifest 仍须明确发布迁移说明。

## 宿主依据

已核对 TauriTavern 官方源码：
https://github.com/Darkatse/TauriTavern/blob/main/src/scripts/extensions.js

`updateExtension()` 在更新成功后调用 `callExtensionHook(fullExtensionName, 'update')`。后者从已加载 manifest 查 hook，并 import 同一个 js 入口，非 chatSurface hook 最长等待 5 秒。所以本实现的 onUpdate 只排队，不阻塞宿主更新界面。首次从 native.13 或更早升级，内存里的旧 manifest 没有 update hook，必须重进一次。

## 人类验收步骤

1. 在手机 TT 的扩展管理里更新二改智库，第一次升级本版后退出重进一次，版本应为 `0.8.60-native.14`。
2. 在聊天输入框写几个字但不发送，进入扩展设置点「重载智库」。等几秒出现「智库已自动重载」，输入框文字应还在。
3. 正在生成图片时点重载，应等当前任务完成后再切换，旧任务不应被取消。
4. 如果提示等待，保存并关闭智库面板或漫画阅读器，回到聊天页面，等重载成功提示。
5. 下次发布新版本后，在扩展管理点击更新即可。以「智库已自动重载 · 版本」提示为准；宿主通用的“刷新生效”提示可能仍然出现。

## 给下一个人的话

不要把后台下载或自动安装加入这次功能。等待期间不强关用户编辑器，不重载整个宿主。将来增加异步控制器时把完整生命周期纳入活动计数；新编辑面板需加入 canReload 的遮挡检查。自动恢复需要依赖旧运行时已有的 stop 清理，继续维护可重复启动和完整释放。

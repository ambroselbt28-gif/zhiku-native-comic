# Z007 按所选图片类型补缺

## 交付

版本为 `0.8.54-native.7`，分支为 `task/Z007-backfill-image-types`。
安装仓库为 `https://github.com/ambroselbt28-gif/zhiku-native-comic`。

用户反馈只有漫画的楼层也跳过正文补图。旧判断将漫画、普通插图和正文内嵌图相加，导致两种补图互相跳过。本次预览与实际执行均按所选类型判断已有图片。

普通插图检查标记图片与正文内嵌图，漫画检查当前候选的漫画图片。只有漫画的楼层可以补普通插图，只有普通插图的楼层可以补漫画。任一出图或正文方案流程在途时，继续使用楼层忙碌保护。

窗口提示说明两种类型分别补缺，预览统计和跳过原因显示具体类型。

## 文件与接口

- `src/image-backfill.js` 的内部检查接收类型，`preview(from, to, mode = 'ill')` 增加可选类型参数。窗口传入当前选择，两个参数的既有调用默认统计普通插图。
- `tests/image-backfill.mjs` 对源码和发布代码检查仅漫画、仅插图、两者都有、内嵌图、重复补图及跨类型忙碌保护。
- `dev/comic-browser.html` 在正式入口切换类型并检查预览变化。
- 构建脚本、扩展清单、包信息和正式 `runtime.js` 更新版本。

## 人类验收步骤

1. 在手机 TT 扩展管理里更新智库二改，退出并重开 TT，关于页确认版本为 `0.8.54-native.7`。
2. 找一个只有漫画、没有正文插图的角色回复，记下聊天显示的楼层编号。
3. 打开智库「漫画 → 补未生图楼层」，类型选「普通插图」，起止均填写该编号。预览应显示可补 1 楼。
4. 点击「开始补图」，等待该楼新增正文插图。
5. 再补同一楼的普通插图，应显示已有普通插图并跳过。
6. 如有只有普通插图的楼层，切换「漫画」后填写该楼，应可以补漫画。

## 给下一个人的话

预览与调度需持续使用同一个所选类型。扩展补图统计时保留跨类型忙碌保护，防止两个流程同时改动同一条消息。
